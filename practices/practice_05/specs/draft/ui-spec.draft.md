# UI Specification (Draft / Pre-Negotiation)
**Team:** Frontend / UI Engineering (Team 1)  
**Feature:** Favorites & Wishlist for VkusMart  
**Status:** DRAFT (Awaiting backend alignment)  
**Date:** 2026-10-23  

---

## 1. Обзор фичи (User Experience)
Пользователь должен иметь возможность отмечать понравившиеся товары в каталоге и результатах поиска, просматривать список избранного в отдельной шторке/модалке, видеть бейдж количества в навигационной панели и иметь возможность в один клик перенести все товары из избранного в корзину покупок.

---

## 2. Экраны и элементы интерфейса

### 2.1. Кнопка «Избранное» на карточках товаров
* **Расположение:** В верхнем правом углу каждой карточки товара (каталог, темы, результаты поиска).
* **Внешний вид:**
  * Не в избранном: прозрачная кнопка с контурным сердечком (`♡`).
  * В избранном: розовая/красная заливка (`❤️`) с плавной анимацией масштабирования (scale pop).
* **Действие:**
  * Клик переключает состояние локально.
  * Если товар не был в избранном — отправляет запрос на добавление.
  * Если товар был в избранном — отправляет запрос на удаление.

### 2.2. Кнопка доступа к избранному в шапке (Navbar)
* **Элемент:** Кнопка `#favorites-btn` рядом с корзиной.
* **Текст:** `❤️ Избранное <span class="badge" id="fav-count">0</span>`.
* **Поведение:** Клик открывает модальное окно `#favorites-modal`.

### 2.3. Модальное окно избранного (`#favorites-modal`)
* **Заголовок:** «Моё избранное» + крестик закрытия.
* **Список элементов (`#favorites-list`):**
  * Мини-карточка товара: наименование, категория, цена, калорийность, белок.
  * Кнопка «Удалить из избранного» (иконка корзины или крестик).
  * Кнопка «В корзину» для отдельного товара.
* **Подвал модалки:**
  * Общая сумма избранного: `Итого: X ₽`.
  * Кнопка «Перенести все в корзину» (`#move-all-to-cart-btn`).
  * Кнопка «Очистить избранное» (`#clear-fav-btn`).
* **Пустое состояние (`#favorites-empty`):**
  * Если в избранном 0 товаров: сообщение «Ваш список избранного пуст. Добавьте товары из каталога сердечком!».

## 3. Предполагаемое взаимодействие с API (первоначальное видение UI)

> [!WARNING] Несогласованные предположения UI-команды
> 1. UI планировал использовать формат `camelCase` (`productId`).
> 2. UI ожидал от сервера только статус успеха (`{"status": "ok"}`), рассчитывая, что сами товары уже хранятся в DOM/JS.
> 3. UI предполагал переносить товары в корзину самостоятельно — циклическими POST-запросами в `/api/cart/calculate`.

### 3.1. Добавление в избранное:
* **Запрос:** `POST /api/favorites`
* **Body:**
  ```json
  {
    "productId": "prod-1",
    "userId": "guest"
  }
  ```
* **Ожидаемый ответ:**
  ```json
  {
    "status": "ok"
  }
  ```

### 3.2. Удаление из избранного:
* **Запрос:** `DELETE /api/favorites/prod-1`
* **Ожидаемый ответ:**
  ```json
  {
    "status": "deleted"
  }
  ```

### 3.3. Получение списка избранного:
* **Запрос:** `GET /api/favorites`
* **Ожидаемый ответ:**
  ```json
  {
    "ids": ["prod-1", "prod-3"]
  }
  ```

## 4. Состояния и обработка ошибок (UI)
* **Offline / Network Error:** Если запрос не удался, вернуть иконку сердечка в прежнее состояние и показать всплывающее уведомление (toast) «Ошибка соединения».
* **Конфликт (товар уже добавлен):** Ничего не делать, оставить сердечко активным.
* **Загрузка:** Пока идет запрос к `/api/favorites`, показывать спиннер в модалке.
