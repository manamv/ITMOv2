Для реализации принципа Spec-Driven Development (SDD) был выбран фреймворк Spec-Kit как альтернатива рассмотренному на семинаре OpenSpec.

Сравнительный анализ фреймворков

Критерий OpenSpec (семинар) Spec-Kit (наш выбор в ДЗ)
Основная парадигма Пошаговый конвейер правок одного разработчика: explore → propose → apply → archive. Контрактное взаимодействие независимых команд: Team UI + Team Logic → Shared Contract.
Механика контракта Дельта-спецификации (диффы требований к существующей системе). Единый согласованный протокол API/схем данных с версионированием (OpenAPI / JSON Schema).
Изоляция команд Один общий контекст агента. Раздельные спецификации команд, предотвращающие загрязнение контекста агентов.
Преимущество в brownfield Детерминированный CLI для быстрой синхронизации изменений. Гарантирует 100% совместимость фронтенда и бэкенда до написания кода.

💡 5. Рефлексия: Чему научились (1 балл)

1. Контракт ДО кода спас часы на интеграции: Если бы команды начали программировать по своим драфтам, пришлось бы переписывать сериализаторы (camelCase vs snake_case), обрабатывать 400-е ошибки при кликах и бороться с рассинхронизацией цен.
2. Идемпотентность — основа надёжного UI: Быстрый двойной клик пользователя по сердечку не должен генерировать ошибки в консоли браузера. Сервер должен спокойно отвечать 200 OK с актуальным состоянием.
3. Spec-Kit обеспечивает четкие границы для AI-агентов: Агенту фронтенда не нужно сканировать весь бэкенд, а агенту бэкенда — разбираться в верстке. Контракт служит точным изолированным интерфейсом.
