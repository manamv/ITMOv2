Отчёт ведёт OpenCode по фактическим результатам команд и вашим сообщениям в чате. Поручите агенту заполнить разделы и показать diff. Выводы студента он записывает после обсуждения; отсутствующие измерения отмечает как невыполненные.

## Окружение

- **ОС / CPU / GPU / RAM / VRAM / свободный диск:**
  Windows 11; AMD Ryzen AI 9 HX 370 (12C/24T); AMD Radeon 890M (iGPU, DirectML); RAM 32 GB; VRAM shared; свободный диск: D: 616 GB, C: 63.5 GB.
- **Ollama / OpenCode / Python, версии:**
  Ollama 0.34.4; OpenCode 1.18.33 (запуск через Bypass ExecutionPolicy на процесс); Python 3.14.0.
- **Модель, разработчик, семейство, тег и ID:**
  Qwen2.5 Instruct 7B, разработчик Alibaba Cloud, семейство Qwen2.5, тег `qwen2.5:7b-instruct-q4_k_m`; локальные образы `itmo-local` и `itmo-agent`.
- **Формат, квантизация, лицензия, источник:**
  GGUF через Ollama; квантование Q4_K_M (~4.7 GB); лицензия Apache-2.0; источник: официальная библиотека моделей Ollama.
- **Фактический контекст, размещение CPU/GPU:**
  `itmo-local`: num_ctx=4096; `itmo-agent`: запрошенный параметр num_ctx=65536, фактический контекст по `ollama show` составил 32768; размещение: 100% CPU (`ollama ps`).
- **Почему выбрана эта конфигурация:**
  Обязательно требовалось высокое качество понимания русского языка и развитые кодовые навыки; Qwen2.5 7B Instruct обеспечивает оптимальный баланс точности и потребления ресурсов на 32 GB RAM без переполнения памяти.

- **Три прогретых повтора (Hot Runs):**
  - Зафиксированы в `baseline.json`, `hot43.json`, `hot44.json`: веса уже находятся в RAM, поэтому время подгрузки составило всего **0.003–0.007 с**, а время генерации сократилось до **1.47–2.01 с**.

- **Метод измерения и единицы:**
  - Время генерации и количество сгенерированных токенов брались напрямую из служебных полей ответа Ollama: `eval_count` и `eval_duration` (нс).
  - Скорость декодирования рассчитывалась по формуле: `decode_tokens_per_second = eval_count / (eval_duration / 1e9)`.
- **TTFT (Time to First Token) и обработка промпта:**
  - Запросы отправлялись в непотоковом режиме (`stream: false`), поэтому TTFT напрямую соответствует времени обработки входного контекста (`prompt_eval_duration`), которое на прогретых прогонах составило **72–89 мс** для контекста из 189 токенов.

## Вывод

- **Обнаруженные ошибки и ограничения среды:**
  1. *Лимит контекста:* Запрошенный в Modelfile размер контекста `num_ctx=65536` для `itmo-agent` фактически был ограничен значением `32768` токенов (зафиксировано в `ollama show itmo-agent`), так как драйвер и квантованная модель имеют аппаратный потолок на текущей сборке.
  2. *Политика выполнения PowerShell:* Запуск глобального CLI OpenCode блокировался системной политикой Windows ExecutionPolicy, что потребовало явного вызова с флагом `-ExecutionPolicy Bypass`.
  3. *Утилита `make`:* В стандартной Windows-среде отсутствует `make`, поэтому запуск учебного пайплайна производился через прямой запуск `python -m unittest`.
- **Итоговый выбор конфигурации:**
  - Для работы над проектом выбрана конфигурация **Qwen2.5 7B Instruct (`qwen2.5:7b-instruct-q4_k_m`) с системным промптом (Режим B)** при `temperature=0.2`.
  - Причина: системный промпт полностью исключает галлюцинации на вопросах с ложной предпосылкой и вопросах без ответа, заставляя модель опираться исключительно на фактический код и указывать первоисточники.
- **Что осталось непроверенным:**
  - Запуск через WSL с нативным GNU Make и замер скорости при включенном GPU-ускорении через DirectML/ROCm.
