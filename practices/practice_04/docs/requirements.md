# Требования к проекту VkusMart: Smart Thematic Grocery & Meal Prep Assistant

## 1. Назначение системы
VkusMart — интеллектуальный ассистент и сервис тематических продуктовых подборок на основе каталога продуктов (формат ВкусВилл / здоровое питание). Сервис предоставляет пользователям готовые корзины по темам («Быстрый студенческий ужин», «Кето-ланч», «ПП-рацион», «Сладкое без сахара»), автоматический расчет стоимости и КБЖУ, а также интерфейс интеграции с агентами через протокол MCP (Model Context Protocol).

## 2. Архитектурные компоненты
1. **Каталог продуктов (`app/catalog.py`)**:
   - База товаров: идентификатор, название, категория, цена (руб), масса/объем, калорийность (ккал на 100г/порцию), БЖУ (белки, жиры, углеводы), теги (keto, gluten_free, sugar_free, vegan, budget) и список аллергенов (lactose, nuts, gluten, seafood).
2. **Сервис подборок и корзины (`app/services.py`)**:
   - Формирование тематических наборов с фильтрацией по бюджету и исключению аллергенов.
   - Агрегация корзины: расчет суммы, калорий, БЖУ, скидок.
3. **MCP Сервер (`mcp_server/server.py`)**:
   - Сервер по спецификации Model Context Protocol (JSON-RPC 2.0 stdio).
   - Предоставляет tools:
     - `get_theme_bundles`: получение подборок с фильтрами.
     - `search_products`: поиск товаров по ключевым словам и диетическим критериям.
     - `calculate_cart_nutrition`: детальный расчет пищевой ценности и бюджета корзины.
   - Валидация входных данных и строгая обработка ошибок с информативными сообщениями.
4. **Веб-интерфейс (`app/static/`) и HTTP API (`app/server.py`)**:
   - Интерактивный UI с выбором тем, интерактивной корзиной и панелью живого вызова MCP («MCP Console»).

## 3. Фича A (Входная валидация, фильтрация аллергенов и бюджетные рамки)
- Валидация поисковых запросов (минимальная длина 2 символа, санитизация от спецсимволов).
- Валидация бюджета: бюджет должен быть строго положительным числом (> 0).
- Исключение продуктов, содержащих указанные пользователем аллергены (lactose, nuts, gluten и др.).
- Проверка категорий: допустимы только существующие категории каталога. При некорректной категории возвращается структурированная ошибка.

## 4. Фича B (Расчет динамической скидки и Graceful Fallback с рекомендацией альтернатив)
- Расчет динамической скидки: при сумме корзины от 1500 ₽ применяется скидка 7%, от 2500 ₽ — 12%.
- Проверка баланса БЖУ: индикатор перевеса углеводов/жиров с рекомендацией скорректировать корзину.
- Graceful Fallback: если по жестким фильтрам (например, слишком низкий бюджет при множестве аллергенов) найдено 0 товаров, сервис не падает, а возвращает статус `fallback_applied`, ослабляет некритичные фильтры и предлагает ближайшие альтернативы.

## 5. Требования к проверкам (Runner)
- Все проверки должны выполняться через `scripts/check.sh` (или кроссплатформенный `python scripts/check.py`).
- Runner выполняет:
  1. Синтаксическую проверку и проверку типов.
  2. Запуск unit- и integration-тестов (включая тесты MCP сервера).
  3. Проверку инвариантов каталога (неотрицательные цены и калории).
- Код возврата: `0` при успешных проверках, ненулевой при падении любого шага.
