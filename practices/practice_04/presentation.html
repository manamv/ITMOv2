О проекте VkusMart

Интеллектуальная система формирования тематических продуктовых подборок и рационов на основе каталога продуктов ВкусВилл. В проекте развернута полноценная среда AI-агента с жестким контролем целостности кода и интеграцией по протоколу MCP.

Ключевые ссылки на локальные файлы:

📄 AGENTS.md — правила проекта

⚙️ opencode.json — конфигурация MCP

🧠 SKILL.md — навык кураторства

🔌 mcp_server/server.py — MCP сервер

⚡ scripts/check.py — единый runner

📝 reflection.md — рефлексия разработчика

Метрики верификации:

• Автоматические тесты: 25 из 25 пройдены (100%)

• Время полного прогона: 0.04 секунды

• Модули проверки: Синтаксис, Каталог, Фича A, Фича B, MCP сервер

• Поддержка ОС: Windows, macOS, Linux (кроссплатформенный runner)

1. Настроенная среда (5 баллов)

Каждое подключение в проекте обосновано и выполняет конкретную задачу в цикле разработки.

Обоснование подключений:

1. AGENTS.md — предотвращает деградацию контрактов и запрещает ослабление проверок runner ради галочки.

2. Hook check-after-edit.js — перехватывает сохранение файлов (`execute.after`) и сразу запускает доверенный runner, не позволяя агенту накапливать скрытые синтаксические или логические ошибки.

3. opencode.json — объявляет локальный MCP сервер `vkusmart-mcp` (stdio) и удаленный `context7` для документации библиотек.

4. Runner scripts/check.py — единый авторитет качества кода. Завершается с кодом 0 только если синтаксис, структура каталога и все 25 тестов зеленые.

Код Hook: .opencode/plugins/check-after-edit.js

ctx.tool.hook("execute.after", async (event) => {
  const editTools = ["write_file", "edit_file", "replace_file_content"];
  if (editTools.some(t => event.tool?.name?.includes(t))) {
    const res = spawnSync(pythonBin, ["scripts/check.py"]);
    event.result.autoCheckStatus = res.status === 0 ? "PASS" : "FAIL";
  }
});

2. Навык и содержательная автоматизация (2 балла)

Разработан специализированный навык .opencode/skills/thematic-grocery-curator/.

Устройство навыка:

• SKILL.md: Триггеры, системные правила составления корзин, пропорции БЖУ и чеклист безопасности по аллергенам.

• rules/nutrition-guidelines.md: Стандарты здорового питания (ВОЗ) и целевые коридоры для тем: «Здоровый баланс», «Студент», «Кето», «Без сахара».

• scripts/validate_bundle.py: Содержательный скрипт автоматизации. Проверяет соотношение калорий, вычисляет долю белков/жиров/углеводов и выдает оценку сбалансированности Health Score (0-100%).

3. Собственный / выбранный MCP сервер (2 балла)

Сервер mcp_server/server.py реализует стандарт Model Context Protocol (JSON-RPC 2.0 stdio) и предоставляет 3 полезных инструмента.

Реализованные инструменты (Tools):

1. get_theme_bundles: получение подборок с фильтрами по бюджету и аллергенам.

2. search_products: поиск по названию, категории, калориям и тегам.

3. calculate_cart_nutrition: расчет корзины, динамических скидок и полного баланса КБЖУ.

Успешный вызов (200 OK):

// Request: get_theme_bundles { theme_id: "theme-student" }
{
  "isError": false,
  "content": [{
    "text": "{\n  \"bundles\": [{\n    \"id\": \"theme-student\",\n    \"title\": \"Студенческий ужин до 500 ₽\",\n    \"actual_price\": 385.0,\n    \"is_within_budget\": true\n  }]\n}"
  }]
}

Обработка ошибочного входа (Handled Error):

Сценарий: Пустой поисковый запрос

// Request: search_products { query: "   " }
{
  "isError": true,
  "content": [{
    "text": "{\n  \"error\": true,\n  \"code\": \"EMPTY_QUERY\",\n  \"message\": \"Поисковый запрос не может быть пустым.\"\n}"
  }]
}

Сценарий: Отрицательный бюджет

// Request: get_theme_bundles { max_budget: -100 }
{
  "isError": true,
  "content": [{
    "text": "{\n  \"error\": true,\n  \"code\": \"INVALID_BUDGET\",\n  \"message\": \"Бюджет должен быть строго положительным числом, получено: -100\"\n}"
  }]
}

4. Реализация фич A и B (TDD, Worktree & QA Subagent)

Фича A (Входная валидация & Аллергены)

• Реализована по TDD в основной ветке `practice_4`.

• Жесткое исключение аллергенов (`lactose`, `gluten`, `nuts`, `seafood`).

• Валидация диапазонов цен, калорий и существующих категорий.

• Фиксация контекста в docs/HANDOFF.md.

Фича B (Скидки, БЖУ & Graceful Fallback)

• Реализована в отдельном git worktree (`practice-04-b`).

• Ступенчатые скидки: 1500 ₽ -> 7%, 2500 ₽ -> 12%.

• Graceful Fallback: мягкое расширение диапазона при 0 совпадений без нарушения фильтра аллергенов.

• Проведена независимым субагентом @tester (25 тестов PASS).

• Слияние: git merge --ff-only practice-04-b.

5. Инженерная рефлексия (reflection.md)

Ключевые выводы:

1. Что помогло: Строгий контрактный подход (`AGENTS.md` + `style-guide.md`) и автоматический хук проверок после сохранения файлов. Любая ошибка в коде выявлялась за миллисекунды.

2. Что мешало: Ограничения LSP в текущей версии OpenCode 2.0.20 (компенсировано внешним runner) и то, что `git worktree` не копирует `.venv` (компенсировано поиском интерпретатора в `check.py`).

3. Где потребовалось вмешательство человека: Реализация стемминга русских слов при поиске («индейка» vs «индейки»), запрет ослабления фильтра аллергенов в fallback из соображений безопасности и создание интерактивной MCP Console для защиты.
