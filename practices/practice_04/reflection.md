# Рефлексия по Практике 4: Среда агента, Skill и MCP в проекте VkusMart

## 1. Контекст и архитектурный замысел
В рамках Практики 4 разрабатывалась система **VkusMart** — интеллектуальный ассистент формирования тематических продуктовых наборов и рационов на основе каталога продуктов (формат ВкусВилл / здоровое питание). Главная цель заключалась не просто в написании кода фич, а в выстраивании полноценной, самопроверяемой среды агента (Agent Harnessing), включающей правила `AGENTS.md`, хук автопроверки `check-after-edit.js`, предметный навык `thematic-grocery-curator`, интеграцию с MCP сервером и независимое ветвление через `git worktree`.

---

## 2. Что помогло

1. **Контрактный подход через `AGENTS.md` и `style-guide.md`:**
   Четкая фиксация ограничений («не ослаблять runner», «не менять сигнатуры MCP без согласования», «fail-fast с понятными кодами ошибок») позволила агенту с первой итерации генерировать код с правильными типами данных, неизменяемыми `dataclass(frozen=True)` и без лишних внешних зависимостей.
2. **Автоматический Runner (`scripts/check.py`) + Hook:**
   Наличие единой команды, объединяющей синтаксический анализ, валидацию инвариантов каталога и запуск `pytest`/`unittest`, устранило проблему «скрытых поломок». Каждый раз, когда агент редактировал код, результат проверки мгновенно возвращался в контекст.
3. **Изоляция ветки B через `git worktree` и QA-субагент `@tester`:**
   Разработка Фичи B в отдельном worktree позволила сохранить контекст Фичи A в неприкосновенности. Вызов независимого субагента `@tester` перед слиянием доказал свою эффективность: он беспристрастно прогнал весь набор из 25 тестов, проверил пограничные условия скидок и убедился в отсутствии регрессий. Fast-forward слияние `git merge --ff-only practice-04-b` прошло без единого конфликта.
4. **Разработка собственного MCP сервера (`mcp_server/server.py`):**
   По спецификации Model Context Protocol (JSON-RPC 2.0 stdio, версия 2024-11-05) с нуля реализован собственный сервер, предоставляющий 3 инструмента: `get_theme_bundles` (подборки рационов по бюджету/аллергенам), `search_products` (умный поиск с нормализацией) и `calculate_cart_nutrition` (расчет БЖУ и ступенчатых скидок 7%/12%). Сервер строго валидирует входные параметры и возвращает типизированные коды ошибок (`EMPTY_QUERY`, `QUERY_TOO_SHORT`, `INVALID_BUDGET`, `UNKNOWN_CATEGORY`, `PRODUCT_NOT_FOUND`). Это позволило агенту взаимодействовать с доменной логикой приложения через стандартизированный протокол.
5. **Интеграция с официальным удаленным сервером ВкусВилл (`https://mcp.vkusvill.ru/mcp`):**
   В дополнение к собственному серверу исследована работа внешнего продакшен-сервера ВкусВилла. Выяснилось, что удаленный сервер работает по протоколу JSON-RPC 2.0 stateless HTTP POST и строго требует заголовок `Accept: application/json, text/event-stream` (иначе возвращается HTTP 406). Был реализован клиент `mcp_server/vkusvill_client.py` на стандартной библиотеке Python (`urllib.request`), подключенный в `opencode.json` и покрытый тестами на успешный поиск (`q: "гречка"`), получение скидок (`vkusvill_products_discount`) и валидацию ошибочного пустого запроса (`code: -32602 / invalid_input`).

## 3. Что мешало и с какими ограничениями столкнулись

1. **Ограничения LSP и динамического контекста в OpenCode 2.0.20:**
   Как отмечено в материалах лекции, в OpenCode 2.0.20 language servers и прямая LSP-диагностика на лету ограничены. Это подтвердило необходимость компенсации через внешний CLI runner (`scripts/check.sh`), возвращающий ошибки синтаксиса и типизации через стандартный вывод.
2. **Нюансы изоляции окружения в Git Worktree:**
   Команда `git worktree add` создает отдельное дерево рабочей копии файлов, но не переносит виртуальное окружение `.venv` и не изолирует системные процессы. Пришлось заранее предусмотреть в `scripts/check.py` умный fallback: скрипт проверяет наличие `.venv` в текущей директории, а при его отсутствии в worktree прозрачно использует интерпретатор родительского репозитория или системный Python.
3. **Локальный файл исключений `.git/info/exclude`:**
   В процессе работы выяснилось, что в локальный `.git/info/exclude` был добавлен `opencode.json`, из-за чего конфигурация MCP не попадала в git. Потребовалось вручную скорректировать правила исключений, чтобы все артефакты среды агента отслеживались в репозитории для сдачи.
4. **Морфология поиска в каталоге продуктов:**
   При первой реализации поиск искал точную подстроку: запрос «индейка» не находил товар «Филе грудки индейки су-вид» из-за склонения. Тест `test_tool_search_products_success` упал, что сразу выявил runner. Пришлось реализовать нормализацию по основам слов (стемминг), благодаря чему поиск стал устойчив к падежам русского языка.

## 4. Где потребовалось вмешательство человека (Senior Decisions)

- **Архитектурный выбор стека для веб-интерфейса:**
  Вместо развертывания тяжелых сборщиков (Webpack/Vite/Next.js), которые создают гигабайты `node_modules` и проблемы с правами запуска скриптов на Windows, было принято решение реализовать чистый, сверхбыстрый Vanilla SPA фронтенд и встроенный HTTP/MCP сервер на стандартной библиотеке Python. В результате приложение запускается одной командой за 0.1 секунды на любой машине.
- **Интерактивная панель «MCP Live Console»:**
  Для наглядной демонстрации ревьюверу была разработана интерактивная вкладка в веб-интерфейсе, которая позволяет прямо из браузера дергать инструменты MCP с реальными параметрами и видеть сырой JSON-RPC ответ сервера как в успешных, так и в ошибочных кейсах.
- **Безопасность при Graceful Fallback (Фича B):**
  При реализации механизма fallback для поиска товаров было заложено жесткое правило: при отсутствии товаров можно ослаблять ценовой диапазон (+30%) или калорийность, но **категорически запрещено ослаблять фильтр аллергенов**, так как это вопрос здоровья и безопасности пользователя.

---

## 5. Итоговый вывод
Практика продемонстрировала, что надежность работы AI-агентов зависит не от объема промпта, а от жесткости инженерного контура: контракты в markdown, перехватчики событий (hooks), изолированные worktree, автоматические раннеры и специализированные субагенты с разделением ответственности.
